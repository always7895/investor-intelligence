# Source diversity audit / 資料來源多元化稽核

Operator rule (2026-09-26): no data product may depend on a single source. 任何資料產品都不得單一依賴一個來源。

Audit of 2026-09-26 (updated the same evening): read-only inventory by Gemini 3.8 (steps of `scripts/run_daily_data_refresh.ps1`, the sealed run and
the Worker readers), verified against the code and the runtime log by the writer. A source that is the statutory
authority (SEC filings, an exchange's own listing or option chain) has no independent free equivalent; there the rule is
met by a cached last good value, an age limit and an explicit unavailability reason, never by a guess.

## Decisions

- Cboe delayed option quotes stay rejected: its official page prohibits automated extraction
  ([PUBLIC_OPTIONS_PROVIDER_RIGHTS_REVIEW](PUBLIC_OPTIONS_PROVIDER_RIGHTS_REVIEW.md)). One read-only request was made to it
  on 2026-09-26 while evaluating, before the review was consulted; it is not used.
- The second US option-chain source is the Nasdaq public option chain, used only for cycles Yahoo cannot read (operator
  2026-09-26: Nasdaq data accepted); its observations carry `rights_status: candidate_local_review`.
- Keyed free APIs (for example Alpha Vantage, OpenDART, FRED) need the operator's own registration; the key is stored
  DPAPI-protected like the SEC contact and never in the repository.
- Cision (news.cision.com) carries Stockholm issuers' MAR releases; its robots.txt allows the release RSS and pages. MFN's
  robots.txt disallows its RSS feeds, so it is not used.
- Research agents reach official keyless data through the read-only MCP server `scripts/public_data_mcp.py` (SEC EDGAR,
  TWSE/TPEx monthly revenue).

## US identity local SEC-cache fallback (2026-10-04)

IMPLEMENTED_UNVERIFIED: source text only, never executed, no live proof and no second-source corroboration. This is a dated implementation note; the matrix above remains the 2026-09-26 audit and is not fresh evidence.

- Trigger: either Nasdaq Trader US directory fails to fetch or parse, or has fewer rows than its minimum. Both US feeds are then replaced as a unit by ONE feed, never mixed. A healthy build never reads the local file; every other market failing still fails the build.
- Source: the raw SEC `company_tickers_exchange.json` already kept at `data/cache/v21/company_tickers_exchange.json` (written by `company_deep_report.ticker_ciks`). The shard builder only reads it: no new request, SEC contact, credential or write.
- Restrictions: a regular file of at most 32 MiB whose mtime is at most 7 days old when the shards are built (a build admission bound, not the age at view time: the publisher can keep the identity shards for up to 8 days) and not in the future (`LOCAL_CACHE_MTIME`: a local file time, not an authenticated acquisition time and not proof of origin); unique string fields `cik`, `name`, `ticker`, `exchange` and equal-width rows; only the exact SEC exchanges `Nasdaq` and `NYSE` are kept (every other value is skipped, never guessed); valid symbol grammar and an integral CIK per row; a name that is 1-300 UTF-16 code units both as stripped and in its normalized (lower-cased, whitespace-collapsed) form, strictly encoded. The Worker counts UTF-16 code units, not Python code points: a supplementary-plane character counts as two, a lone surrogate (a JSON escape can decode to one), an overlong name and a name that grows when normalized are skipped before any de-duplication or count, and are never truncated or repaired. A conflicting duplicate between two eligible rows rejects the file; a skipped invalid-name row never takes part in duplicate detection, so it can conceal a conflict with an eligible row (a bounded admission policy, not a guarantee); at least the Nasdaq Trader minimum of unique accepted rows and both exchanges must be present, otherwise the original US error stands.
- Output: every row has class `REVIEW_REQUIRED` (no stock, ETF or ADR is guessed). The feed `sec-company-tickers-exchange` carries the SHA-256 of the exact local bytes, the file time as `retrieved_at`, `retrieval_basis`, `fallback_for` and the original US error as `fallback_reason` (advisory keys; the Worker ignores them). The root and every shard carry the oldest feed time as `generated_at`, so the publisher's eight-day age check sees the cache's real age.
- Coverage and tradeoff: partial. NYSE American, NYSE Arca, Cboe BZX and IEX listings are absent, and share-class spellings may differ from the Nasdaq Trader directories (the SEC spelling is kept; no alias such as BRK.B for BRK-B is invented, so a price join on a different spelling can be missing). By the original contract the build writes a degraded partial document even when an older, broader last-good document still exists; no last-good selection policy is added here, so degraded coverage can replace broader coverage until the primary feeds work again.
- Status: the build writes the shards atomically, prints `DEGRADED_US_FALLBACK` and exits 2 (not OK). `--if-older-than-hours` never treats a degraded file as fresh, so the next run retries the primary feeds. An unusable cache keeps the original US error and the last good shards.
- Visible behaviour (IDIV2, IMPLEMENTED_UNVERIFIED: source text only, never executed): `REVIEW_REQUIRED` itself is stored metadata and neither blocks nor warns. `cloud/src/v213/global-equity-lookup.ts` shows the fallback warning ONLY for an actual RESOLVED US identity record whose `source_feed` is exactly `sec-company-tickers-exchange` (the renderer reads the record in `result.resolution`; it is not inferred from `result.source` text, a quote or the class). For such a record the title says SEC-cache fallback identity (so the Flex alt text carries it), the text lines and the Flex body carry the notice that the SEC local cache covers Nasdaq and NYSE only in part, that the listing status and security class are not verified against an exchange directory, that the file time is not a verified acquisition time and that any option button is navigation only, the market/exchange is labelled as SEC-stated, a missing Chinese name is stated honestly (an independently sourced Chinese name keeps its source label), and the ordinary wording that the official listing identity was verified is replaced by a fallback disclaimer. Quotes, cross-checks, price sources, option buttons and their order, routing and rights are unchanged (a navigation button is not option availability or trade execution). Ambiguous, unavailable, invalid and snapshot-pin-failure cards are unchanged, so this does not cover absent-record or ambiguous coverage. The user-facing text states no age: the 7-day build bound and the publisher's 8-day retention are not view-time promises, and nothing says that an HTTP request just failed. Verification (tests, a live card check) remains a release prerequisite; this is not a completed or live-proven function.
- Boundary: availability only. It is not independent corroboration of a company claim, not proof of quote or option availability, confers no extra rights and changes no price; the second US price source stays OPEN.

## Ambiguous identity safe selection (2026-10-04)

ISEL1, IMPLEMENTED_UNVERIFIED (source text only, never executed, no live proof). Not a coverage or source-diversity change: no new source, fetch, cache or provider. When the stock lookup resolves to NEEDS_MARKET_SELECTION, `cloud/src/v213/global-equity-lookup.ts` offers a button only for a query it certified on the same pinned snapshot view: the candidate's own symbol plus the first existing suffix (`MARKET_SUFFIX_SCHEMES`) whose canonical venues contain its venue, ASCII without spaces, read back by the existing parser as exactly that symbol and suffix, with a button label of at most 20 characters (the module's own bound). Certification runs the existing query-specific loader (`loadIdentityCatalogForQuery`) and resolver on that exact text and requires RESOLVED to a record whose identity and provenance fields (venue, market, country, symbol, native symbol, name, class, currency, source feed and URL; the optional native and Chinese name fields whenever either record defines them) equal the candidate's; a name query's catalog subset is never reused as certification. At most three validation calls per response (failures included, spent before each read, sequential, no retries; at most six symbol-object reads); a failed or missing shard load gives no button and no legacy-catalog fallback. Each displayed candidate shows one state: a certified query, no suffix route (for example every US venue, and symbols with spaces or longer than 10 characters), not certified (not unique, unavailable or a read failure) or unchecked (budget used; not a claim that a route is unsupported or absent). The renderer accepts the handler's routes only when they are consistent with the result (same candidates and lines, each certified query recomputed); this is an internal consistency check, not authentication of where a result object came from.

Display bound (a reviewed presentation decision, not a filter, source or rights rule): the resolver's candidate list is kept whole internally, but text and Flex show the same deterministic prefix of complete candidate lines in resolver order, at most 10 lines and at most 3000 UTF-16 code units including each line's state, further reduced by the room the fixed card lines leave under this project's 4900-character text bound (the conservative check in `cloud/src/line-messages.ts`, not an official LINE limit); no symbol, name or query is cut, and a first line that does not fit shows none. When lines are omitted the card states the exact displayed/total count and asks for a narrower name or a suffixed symbol; it does not say the omitted candidates are absent, unsupported or validated, and this is not pagination or a completeness claim. A text answer is one message; if the fixed card text fits the 4900 bound but the card plus the candidate block would not, it becomes two text messages, the fixed card first and the bounded candidate block second (only then does the block follow the source and disclaimer lines). A legacy card whose own fixed text already exceeds the bound is still rejected by the existing check; nothing is truncated. Up to three certified queries from the visible lines become buttons; any ambiguous card without one, including an empty list or a direct or legacy result without consistent routes, gets the existing safe navigation buttons, and no query is ever built from a display line. A certified button is navigation only: the next request is resolved afresh on its own snapshot and may answer differently; it is not a quote, option or trading qualification. Non-ambiguous cards, the QDIV1 cross-check, the IDIV2 warnings, prices, options and rights are unchanged. Option-menu ambiguity, resolver-conflict reporting and absent-record UX stay OPEN; verification (tests, a live card check) remains a release prerequisite.

O8 local repair (2026-10-07; independent acceptance pending): the options-menu NEEDS_MARKET_SELECTION branch keeps the first five complete symbol/venue labels in resolver order. Only when more than five candidates exist, both text and Flex state the exact shown/total count and that other listings remain undisplayed; exactly five or fewer adds no omission wording. This closes only the omitted-count implementation item above, not option availability, identity completeness, pagination, rights or live LINE/render qualification.

## Honest absence notice (2026-10-04)

ABS1, IMPLEMENTED_UNVERIFIED (source text only, never executed, no live proof). Not a coverage or source change: no new source, fetch, cache, provider or catalog metadata. When the real stock lookup (`handleGlobalEquityLookup` in `cloud/src/v213/global-equity-lookup.ts`) cannot confirm an identity (UNAVAILABLE), it records internally whether it had a runtime-admitted query catalog (present does not mean complete coverage). The card then states, in text and Flex, that the identity could not be confirmed, that the sealed data may be incomplete or unavailable and the cause is unknown, and that this is not proof that the security does not exist, was delisted, has no options or lacks trading rights. If no catalog was available, the shown body of the resolver's `IDENTITY_CATALOG_UNAVAILABLE:` reason is replaced by a neutral sentence: the resolver's "publisher migration deferred" wording is not an established cause when a shard is missing, malformed or unsealed. No feed list, SEC fallback, listing status or rights are inferred from an absent record (every symbol shard carries the global feed list, so it is no per-query coverage evidence). Resolver, loaders, schema, buttons (still safe navigation), prices, options, rights and every other card are unchanged; results without the internal context (direct or legacy callers) are shown as before. Still OPEN: catalog completeness, identity conflicts (the resolver's conflict removal, the loader's same-key overwrite and the exporter's first-feed-wins de-duplication; lanes ICON1/ICON2) and option-menu absence wording; verification (tests, a live card check) remains a release prerequisite.

## Identity conflict visibility (2026-10-04)

ICON12, IMPLEMENTED_UNVERIFIED (source text only, never executed, no live proof). Not a coverage or source change. `scripts/build_identity_shards.py` no longer keeps only the first feed's row for a venue:symbol: an equal identity from a later row or feed still collapses to the first row (provenance only, never independent corroboration), but a contradictory variant (market, country, name, native name, class, currency or Chinese-name pair differ) is kept after it in stable first-encounter order; name rows are de-duplicated; the root `records` count is retained rows, not unique listings or coverage. `cloud/src/v213/identity-shards.ts` keeps every selected row of a key (a repeated visit of the same row is not a variant; Taiwan-first keeps or drops whole keys). `resolveGlobalIdentity` takes the rows its existing channels reach (suffixed: the indexed spelling on the scheme's venues; bare: the existing symbol and name channels), completes each of their keys once with the key's rows under the canonical symbol index (so a native alias or a name that matches only one variant still reveals a contradictory sibling) and keeps every row it already observed even when that index is incomplete; it returns UNAVAILABLE `IDENTITY_CONFLICT:` when any relevant key has contradictory rows: the complete key set decides, at most five complete keys are shown with shown/total, and no remaining candidate is resolved. Grouping is linear in the touched index entries and candidates; the diagnostic key sort is O(K log K). A source feed or URL difference alone is provenance, not a conflict. Legacy conflict metadata is ignored, and an incomplete index cannot prove that an unobserved conflict is absent. The real stock card and the options identity branch report the conflict without a cause-unknown notice. Not covered: direct-ticker and ADR option answers (they run before identity resolution), other price or name consumers (a COMMON_STOCK variant can enlarge the Yahoo price universe and change its threshold and size outcome; names_for and us_symbols are not conflict-aware), and old shards built with first-feed-wins, which cannot reveal lost variants: a fresh conflict-aware build, sealed publication and fixture and live verification are release prerequisites, not done here.
