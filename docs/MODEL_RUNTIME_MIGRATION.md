## Local model auto-detection

Operator 2026-10-11: the local model was `orca-gptq-nvfp4-q8down` on that day and may change again; confirm that it is detected automatically (verbatim record `R/OPERATOR-STATEMENT-LOCAL-MODEL-ORCA-20261011.txt`). The answer below is read from the code; nothing was changed to produce it.

**Mechanism (legacy discovery, the mode in force while no explicit Strata binding exists).** [`scripts/local_model_endpoint.py`](../scripts/local_model_endpoint.py) tries servers in this order: an explicit base (`II_LLAMA_BASE_URL` or `--base`), the launcher's saved selection (`v213-model-selection.json`), the configured base (`config/local-runtime-independence-v1.json` `primary_reasoner.base_url`), the well-known ports (8080, 11434, 1234, 5001, 8081), then every other loopback TCP listener (`:5000` and `:8000` are never probed). Each probe is one read-only `GET /v1/models`. Per server the wanted model (environment, `--want` or the saved selection; the shipped config names no model) wins when served, else a served model of the same family, else the only model the server lists; several unrelated models with no family match give no automatic choice. Across servers the best match wins (exact, then family, then only); several servers that each offer a different unrelated single model give `LOCAL_MODEL_AMBIGUOUS` unless one of them is the operator's own address (explicit base, `II_LLAMA_BASE_URL`, saved selection base), and the same id on several servers is one model. The result names the served id and callers verify replies against it; nothing is substituted silently. The scheduled [watchdog](../scripts/v213_free_relay_watchdog.ps1) (task `InvestorIntelligence-v213-FreeRelay`: logon plus a 5-minute repetition, registered by [`register-v213-free-relay-task.ps1`](../register-v213-free-relay-task.ps1)) runs the resolver each time. A changed served model or port against the saved state gives `RECONNECT_MODEL_CHANGED` and a bridge restart that re-verifies the served model; no usable result (nothing found, or several unrelated models) gives `IDLE_NO_LOCAL_MODEL` and no automatic choice.

**Dated observation, not configuration (2026-10-11, read-only, recorded in the operator statement file).** `127.0.0.1:8097` serves exactly `orca-gptq-nvfp4-q8down` (`/health` ok, `/v1/models` one entry); nothing listens on `:8080`, `:8081` or `:8082`. These are one-time observations: no config file, test pin or installed file records orca as the intended model.

**What is not automatic.**

- Explicit Strata binding (F04) bypasses all discovery on purpose: with a saved or environment binding, the bound root and model are the only authority, and a different model needs a new explicit save, not detection.
- Nothing in the shipped config pins the model (see Model selection below); `config/v213-model-profile-v1.json` still carries `qwen3.8-flash-next-iq3_s` as a non-binding label for its request settings.
- A detected model is `UNQUALIFIED`: the swap invalidates earlier qualification evidence (see the M4 design) and no capacity or answer-quality claim carries over.
- With several unrelated models listed and no family match, the system waits for the operator's pick (`scripts/select_local_model.ps1`); it never guesses.
- Pi's `.pi/agents/qwen-executor.md` (workspace-local, not tracked here) pins a provider that is not configured; the Pi lane is not covered by this mechanism (HOLD in the workspace `AGENTS.md`).

## Presence, precedence and interrupted writes

Explicit CLI binding, process `V213_RUNTIME_BINDING_JSON` and saved binding, when present, must ALL validate and agree. Null/empty is present-invalid, not omission. Profile selection uses explicit profile input, otherwise `V213_MODEL_PROFILE_JSON`, otherwise saved profile then packaged template; each independently present environment/saved profile must agree. Supplied `Model`/base and `II_LOCAL_LLM_MODEL`/`II_LLAMA_BASE_URL` must also match. There is no stale-environment-wins fallback.

The explicit saved selection is a closed nine-field envelope: version2, product2.1.3, engine, exact model/root, both digests, `model_profile_qualified=false`, `source=EXPLICIT_OFFLINE_INTENT`. Size/type/duplicate/digest conflicts refuse. Saved malformed or orphaned explicit selection is unavailable before bootstrap/discovery. Scalar UI parsers also reject duplicate/extra keys and bounded-file/type mismatches; Python checks original bytes rather than a lossy PowerShell object.

Offline save validates first, atomically replaces a deliberately invalid pending binding, replaces profile and selection, and commits the valid binding LAST. Interrupted writes retain invalid presence and refuse routing; per-file atomic replacement is not a multi-file durability qualification. Explicit replacement is a user action, never automatic repair or guessed follows-model reconstruction. No runtime intent files were created during source implementation.

Launcher ownership of `V213_MODEL_PROFILE_JSON`/`V213_RUNTIME_BINDING_JSON` is PROVENANCE, not value equality. A key is owned only if this launcher introduced it while the key was absent, or replaced a value it still owns that nobody changed; an owned value that was externally replaced or removed loses ownership before any mutation. An unchanged save, Check or Use never adopts pre-existing external intent: it keeps its bytes, is neither rewritten nor owned, and the offline save may still pass because the shared helper sees it equal. A later differing save or removal keeps the external key in the child, so the helper refuses until the external source is cleared outside this path; there is no reset flag or catch-to-legacy. An external profile variable alone is not a routing binding: removal may delete the saved binding while that variable stays untouched, so the guarantee is no hidden deletion or override of external keys, not that profile-only removal is forbidden. Only owned unchanged keys are cleared in a save/removal CHILD and in the parent on removal, so launcher-created intent stays replaceable. A byte-identical external replacement cannot be distinguished from the launcher's own value. The legacy non-explicit selection save still assigns the profile variable without ownership tracking, so a later explicit save with different settings in the same session can fail closed until restart. External conflicts require explicit operator reconfiguration. Desktop save similarly rejects conflicting environment; a specified profile must already have the exact chosen model/settings.

Explicit offline removal leaves an invalid pending binding while removing the selection, then removes binding LAST. Interrupted removal cannot expose a torn routable legacy selection. Active external binding/base/model environment must first be cleared explicitly. Saved profile is retained as settings, not qualification. The selector removal operation can recover an invalid saved envelope without parsing it into permission.

### State machine and drain barrier

`PRECHECK -> RESERVED -> ADMISSION_CLOSED -> DRAINED -> OWNED_OLD_EXITED -> CANDIDATE_READY -> VERIFIED -> COMMITTED -> ADMISSION_OPEN`.

- Record a durable transaction ID and previous-generation manifest before closing admission. Every requester must acknowledge the same closed generation; an unaccounted direct client makes the trial ineligible.
- Wait within a fixed deadline for queued, in-flight and background/reload work to reach zero, with ownership and lease still valid. Cancel only owned requests where the reviewed protocol allows it. A timeout preserves failed evidence and restores the unchanged old generation's admission only after revalidation; it does not justify killing shared work.
- `/v1/unload` is NOT a drain latch: queued work can reload weights and `/v1/load` targets the startup model. Do not implement unload-then-kill or in-place arbitrary weight replacement. A lifecycle trial instead stops only the positively owned, drained old instance using its retained handle/creation identity; waits for that exact process and accounted children to exit; proves old allocations released under the held GPU reservation; then starts ONE candidate in a new owned job. No overlapping large model or second server is allowed, even briefly for a readiness check.
- Keep admission closed while the candidate is checked. Require exact selected metadata plus a complete exact-model answer, strict finish/content and finite latency/resource limits; health-only success is insufficient. These are local runtime proofs, not independent market evidence, research qualification or authorization for LINE delivery. Unexpected model/alias, context, auth requirement, child process, timeout, crash or identity drift enters rollback, never a silent alternate model.
- Only after all checks pass, persist the candidate receipt and read it back; commit selected request intent pointer-last using the existing pending barrier. Verify profile/binding/receipt digests and generation agreement again before opening admission. Invalidate old qualifications on every identity/profile change. A torn write or uncertain commit leaves admission CLOSED and intent unavailable.

### Rollback, interruption and recovery

Keep read-only preimages of the previous executable/model/config/profile/binding/selection, their hashes, and the admission generation; these contain no credentials or raw answers. Never overwrite unique evidence. Rollback first closes admission, drains/stops the positively owned candidate, waits for exact handles and GPU release, then starts only the pinned former instance under the still-held reservation. Restore the previous intent with the same pending barrier and pointer-last/readback rules, revalidate exact metadata AND a complete answer, and only then reopen the old generation. Do not restart merely because the old port is free.

If ownership, reservation, predecessor bytes, filesystem integrity or stop/exit proof is lost, do not kill/restart by PID, invoke global cleanup, reclaim a stale lock, or guess rollback success. Keep unavailable, preserve the journal and emit `RECOVERY_REQUIRED`; another bounded recovery GO must establish ownership afresh. A crashed controller's kill-on-close behavior must be proven for its owned job in native tests; it is not assumed from Python mocks. Recovery reconciles handles/generations and journal readback, including candidate-ready but pointer-not-committed, committed but admission-not-open, failed rollback and lost-lease states. No resume step can broaden authority.
